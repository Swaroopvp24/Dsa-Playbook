# Engineering Deep-Dive: Boyer-Moore Majority Vote Algorithm (Generalized)

## Summary
The provided solution implements the **Boyer-Moore Voting Algorithm**, specifically extended to identify elements appearing more than $\lfloor n/3 \rfloor$ times in an array. 

The core algorithmic intuition relies on the fact that for any array, there can be at most two elements that appear more than $n/3$ times. The algorithm performs a two-pass scan:
1. **Candidate Selection Pass:** Uses two counters to track potential candidates. If a new element is encountered and matches a candidate, its counter increments; if it matches neither and space exists, it becomes a new candidate. If both candidate slots are filled and a new unique element appears, we decrement both counters, essentially "nullifying" three distinct elements.
2. **Verification Pass:** Since the selection pass only identifies candidates that *might* satisfy the condition, a second pass is mandatory to confirm the actual frequencies, as the algorithm can produce false positives (e.g., in cases like `[1, 2, 3]`).

---

## Complexity Analysis

### Time Complexity: $O(n)$
*   **First Pass:** The algorithm iterates through the input array exactly once, performing $O(1)$ operations (comparisons and increments/decrements) per element.
*   **Second Pass:** The algorithm iterates through the array a second time to count the occurrences of `cand1` and `cand2`.
*   Total time complexity is $O(2n)$, which simplifies to **$O(n)$**.

### Space Complexity: $O(1)$
*   The algorithm utilizes a fixed number of integer variables (`ct1`, `ct2`, `cand1`, `cand2`) regardless of the input array size. 
*   The output `List<Integer>` is excluded from auxiliary space complexity as it represents the required return format, not working memory.

## Component Deep Dive

### 1. Candidate Selection Logic
The conditional ladder is structured to prioritize existing candidates:
*   **Match:** If the current number `n` equals `cand1` or `cand2`, we increment the respective counter. This reinforces existing confidence in these candidates.
*   **Replacement:** If a candidate has a count of `0`, it is considered "ejected." The current number replaces it. This is a greedy assignment strategy.
*   **The "Ejection" (Decrement) Phase:** When `n` does not match either candidate and both `ct1` and `ct2` are non-zero, the algorithm decrements both. This represents the destruction of a triplet of distinct elements. By discarding these triplets, the majority elements are guaranteed to survive, as they constitute more than 1/3 of the total set.

### 2. Verification Phase
The Boyer-Moore algorithm is an elimination-based heuristic. If an element appears $\leq n/3$ times, it can still result in a candidate if the surrounding elements satisfy the logic. A simple `if (ct > nums.length / 3)` check is essential to filter out "ghost" candidates generated by the elimination logic.

### 3. Edge-Case Handling
*   **Input size $n < 2$:** The logic handles `[1]` or `[1, 2]` correctly. In `[1, 2]`, `cand1` becomes 1, `cand2` becomes 2. Both counts are 1. The verification fails because $1 \ngtr 2/3$, returning an empty list, which is correct.
*   **Empty array:** The loops are skipped, and an empty list is returned.
*   **Duplicates:** The algorithm is robust against high-frequency duplicates (e.g., `[1, 1, 1, 2, 2, 2]`), where `ct1` and `ct2` would stabilize early.

## Key Insights

### 1. The "Distinct Triplets" Invariant
The efficiency of this approach is rooted in the "Triplet Elimination" invariant: if you remove three distinct elements from a set, the majority element (occurring $> n/3$ times) remains the majority element of the remaining set. The algorithm essentially simulates this removal without modifying the array.

### 2. Initialization Bug Trap
A common pitfall in this implementation is initializing `cand1` or `cand2` to a specific value (e.g., `cand1 = 0`). If `0` is a valid number in the input array, this can interfere with the selection logic. In the provided code, the initial state `ct1 = 0` effectively neutralizes this risk because the algorithm will treat `cand1 = 0` as a placeholder rather than a valid candidate until `ct1` is incremented.

### 3. Comparison Ordering
Note that the `if` conditions are ordered. It is critical to check for `n == cand1` and `n == cand2` *before* checking if `ct == 0`. If the `ct == 0` check were first, a valid candidate that temporarily hits a count of 0 could be overwritten by a new element, losing the candidate state prematurely.
